# v8.5 Player Intelligence — plan wdrożenia

## Cel
Zbudować trwałą, cache-first warstwę Player Intelligence, która tworzy profile zawodników, porównuje dwóch graczy przed meczem, generuje predykcje SHADOW dla tych samych rynków co obecny system, wspiera Generator i jest widoczna w UI oraz statystykach.

## Zasady nadrzędne
- Cache-first / incremental: nie pobierać drugi raz danych, które już mamy.
- match_id = źródło prawdy dla meczu; player_id = trwały profil zawodnika.
- Główny zakres historii: 12 miesięcy; do 24 miesięcy tylko fallback przy małej próbce, szczególnie grass.
- Nawierzchnie osobno: HARD / CLAY / GRASS / INDOOR.
- Okna L5 / L10 / L20 dla każdej nawierzchni.
- BO3 / BO5 rozpoznawane osobno.
- Brak data leakage: profile i predykcje zamrażane przed meczem.
- Brak zgadywania: N/D przy braku wiarygodnej próbki.
- Shadow działa od pierwszego wdrożenia; wpływ produkcyjny dopiero przez gate.

## Player Profile
### Player Core
player_id, ranking/ELO/strength rating jeśli dostępne, wiek, wzrost, ręka dominująca jeśli wiarygodne.

### Match Performance
Asy, double faults, 1st serve in, 1st/2nd serve points won, service/return points won, hold/break, BP faced/saved/created/converted, wynik meczu, czas meczu/odpoczynek jeśli dostępne, siła przeciwnika, tour, turniej, nawierzchnia, BO3/BO5.

### Set Performance
Te same najważniejsze metryki osobno dla S1–S5, jeśli źródło je udostępnia.

### PBP / Early Game Quality
hold1/hold2/hold3, stany po 2/4/6 gemach, łatwy hold vs męczony hold, deuce rate, BP w gemach, reakcja po breaku/rebreaku, 40:15 -> deuce/break tylko jeśli feed to umożliwia. Nie zgadywać winnerów/UE bez danych.

### Mental / Pressure / Resilience
Deciding-set, tie-break, BP saved/converted, close-out rate, comeback rate, po W/L w S1, BO5: 2:0 close, 0:2 comeback, 2:1 close, 1:2 recovery, 2:2 deciding set.

## Okna profilu
Dla każdej nawierzchni: L5 / L10 / L20.
Dla każdej metryki: średnia, n, confidence, trend, volatility, min/max gdzie ma sens, updated_at.

## Korekta o jakość przeciwników
Przechowywać RAW metric + opponent strength + opponent-adjusted metric + confidence.
Główną wagę w matchupie ma adjusted, nie sam RAW.

## Player Matchup Engine
Dla A vs B:
- właściwa nawierzchnia,
- L5/L10/L20,
- freshness + confidence,
- serve A vs return B,
- return A vs serve B,
- pressure A vs resilience B,
- surface strength A vs B,
- adjusted form A vs B,
- BO3/BO5 endurance i zachowanie setowe.

## Pipeline
1. Fixtures / API
2. Restore history + cache
3. Existing tendencies / serve props / PBP
4. Player Intelligence DB refresh incremental
5. Player Profiles per surface L5/L10/L20
6. Player Matchup Engine
7. Current / CatBoost / TabPFN / Dynamic
8. Ensemble
9. Ensemble + Player SHADOW
10. Generator + Player Support Score
11. Freeze
12. Settlement HIT/MISS/Brier
13. Player telemetry + Stats UI

## Cache / pamięć
Docelowo:
- players/<player_id>/profile.json
- players/<player_id>/matches_index.json
- reuse istniejącego matches/<match_id>.json.gz / PBP cache
- player_intelligence/state.json

Przed requestem:
1. Czy match_id jest lokalnie?
2. Czy profil jest świeży?
3. Czy pojawił się nowy zakończony mecz?
4. Jeśli nie -> 0 requestów historycznych.
5. Jeśli tak -> pobrać tylko brakujące dane.

Profil zapisuje last_completed_match_id, last_match_at, profile_updated_at, data_version, source, sample_count per surface/window, missing_fields.

## API Budget
Priorytet:
1. fixtures / settlement
2. obecny PBP produkcyjny
3. Player Intelligence dla aktualnych meczów
4. background expansion tylko z wolnej kwoty

Przy niskim budżecie używać cache i oznaczać stale/partial zamiast usuwać profil.

## SHADOW + Production Gate
Równolegle liczyć:
- Player Intelligence
- Ensemble
- Ensemble + Player Shadow

Metryki: accuracy, Brier, log loss, n, per market, per surface, per tour, per confidence tier.

Po promocji przykładowy limit wpływu:
- HIGH do ±4 pp
- MEDIUM do ±2 pp
- LOW minimalny/informacyjny
- N/D = 0

## Generator
Player Support Score:
+10 mocno wspiera / +5 wspiera / 0 neutralny / -5 ostrzega / -10 mocno przeciw.
UI np. 🧬 PLAYER +7 albo 🧬 PLAYER -6 ⚠ z 2–3 powodami.

## UI meczu
Kompaktowa karta PLAYER INTELLIGENCE:
surface + quality, L5/L10/L20, matchup edge, serve edge, return edge, pressure edge, trend/form, confidence.
Szczegóły rozwijane.

## Stats
Karta:
- Player Intelligence
- Ensemble
- Ensemble + Player Shadow

Wykres trendu ostatnich 10/20/50 rozliczeń.
Filtry ALL/HARD/CLAY/GRASS/INDOOR + market + tour.
Widoczne accuracy, Brier, n, trend, quality distribution.

## BO3 / BO5
Nie zakładać, że deciding set = set 3.
BO5: S4/S5, 2:0 close, 0:2 comeback, 2:1 close, 1:2 recovery, 2:2 deciding, performance decay/endurance S1–S5.
Brak danych BO5 -> N/D.
